## Architecture

- **Config**: hugo.yaml. `enableGitInfo: true` — posts can omit `lastmod` and Hugo falls back to the git commit date; do not disable without auditing every post. `frontmatter.lastmod` puts a hand-set `lastmod` ahead of the git date, so structural pages keep the date their content last changed rather than their last commit.
- **Layouts**: hand-rolled, no theme/submodule. `baseof.html` owns the `<main id="main">` element; templates override the `main-class` block (default `prose`).
- **Archetypes**: archetypes/default.md (pages — `lastmod` only) and archetypes/posts.md (posts — `date` only, no `lastmod`); the asymmetry is load-bearing — posts deliberately omit `lastmod` so `enableGitInfo` backfills it from the git commit date
- **Front matter schema**: implicit. Archetypes scaffold `title` + dates + `draft`, but real posts also carry `description`, `tags`, sometimes `aliases`/`series`/`created`. The schema is enforced by the upstream publisher, not Hugo. `layouts/partials/description.html` falls back `.Description → .Summary → Site.Params.description`, so a missing `description` degrades gracefully rather than failing.
- **Shortcodes**: `callout` and `mermaid` are reference templates from `../obsidian-publisher/hugo-shortcodes/` — keep in sync if the publisher's output format changes. Mermaid loads from jsDelivr with an SRI hash via `layouts/partials/mermaid.html`, conditionally on `.HasShortcode "mermaid"` — bumping the pinned version requires recomputing the `integrity` hash.
- **Generated text files**: `robots.txt`, `site.webmanifest`, `vcard.vcf`, `llms.txt` render from `layouts/` templates via custom output formats on the home page — do not re-create them under `static/`

## Content Provenance

Posts in `content/posts/` are generated by the `obsidian-publisher` plugin from the notes vault (`../notes/published/`). Direct edits to published posts are overwritten on the next publish — treat them as read-only output. Only structural pages (`content/_index.md`, `about.md`, `now.md`, `uses.md`, `books-i-have-read.md`, `books-i-may-read.md`) are safely edited in this repo. The two books lists began as published posts and were moved here in #862; they are now hand-edited, not publisher output. Pages with `showUpdated: true` print an "Updated" line from `lastmod`, so bump `lastmod` when editing them. See `../notes/Publishing Pipeline.md` for the full theory.

## Testing

There is no end-to-end test of the publish → render pipeline. The strict Hugo build (`--panicOnWarning` in `task check` and in `wrangler.jsonc`'s `build.command`, which every Workers Build runs) catches missing shortcodes, broken refs, and template errors — but anything subtler is caught by the author visually reviewing published posts. Publish is the integration test.

`task links` runs `lychee` over `public/` (external links and anchors). It is not part of any deploy. Broken links in published posts are fixed in the notes vault, not here.

## Deployment

A Cloudflare Worker at `philoserf.com`, deployed by Workers Builds on every push to `main` (other branches get version uploads, so a merged publisher PR deploys and an open one only builds). `wrangler.jsonc`'s `build.command` is the whole build, the same on a Mac (`task deploy`) and in the build image, so change the build there and nowhere else. Workers Builds clones shallow, and `enableGitInfo` then dates every post to the head commit, so `build.command` fetches full history before Hugo runs. A run of identical post `lastmod` dates in `sitemap.xml` means that step stopped working. A daily cron trigger runs `worker.js`, the Worker's only code, which POSTs the Worker's deploy hook (the secret `DEPLOY_HOOK`) to rebuild for future-dated posts. Its `fetch` handler only hands unmatched requests back to asset serving. The hook only reports that it accepted the call, so a failed build shows in the Workers Builds dashboard.
